# Convoy Mesh — manual ping candidate (CI-built; field test pending)

**Branch:** `experiment/manual-ping-20261114`, based on the currently published pedestrian experimental app branch (PR #4). This branch is not PR #5, is not merged or published, and does not change the public APK.

**Goal:** One manually authorized synthetic connectivity event from a phone to the existing PostHog EU project. Added `ManualPingCard` to **Test log** only. No automatic telemetry, no background events, no BLE/GPS/track reading, no persistent token, no cached queue, no retry. It does not assert cloud storage on HTTP success. The app embeds the ingestion-only project token at build time using the already-existing GitHub Actions secret `CONVOY_LAB_POSTHOG_TOKEN` via a temporary restricted file and Flutter dart-define. The source does not contain a real token, and CI must fail closed if the secret is absent. A project token is write-only and public in a client binary, unlike a personal API key. Pressing the button authorizes exactly one event. There is no separate token input, checkbox, background sending or retry.

**Single-event contract:** `https://eu.i.posthog.com/i/v0/e/`, event `cm_lab_ping`, synthetic random per-attempt `distinct_id`, `ping_id`, `$process_person_profile=false`. Independent readback in PostHog must match the ping ID and show exactly one accepted row. Do not confuse transport HTTP success with PostHog storage. Device transport/IP is processed by PostHog even though the payload contains no real user data. Existing PostHog project is on Free and anonymizes IP, to be rechecked before field trial. Do not link the per-attempt ID to the public BLE participant ID.

**Installation separation:** `-PconvoyPingLab=true` produces package `com.example.convoy_mesh.pinglab2` and label `Convoy Ping LAB 2`, leaving both `com.example.convoy_mesh.pedestrianexp1` and `com.example.convoy_mesh.pinglab` untouched. Changed app identity avoids potential debug-signing upgrade incompatibility. Incremented version `0.7.7-pinglab+11`. The existing Android workflow includes a branch-specific build of this identity, without changing the historic experimental app build. It does NOT automatically publish to a release. Full CI checks must pass before field installation. Do not run the two Convoy packages simultaneously.
